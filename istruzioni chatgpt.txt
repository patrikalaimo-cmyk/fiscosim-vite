- P5-FINAL — Audit complessivo positivo

Punti blindati P5:
1. Controparte patrimoniale fornitore/cliente
   - È il conto piano conti fornitore/cliente.
   - Esempi:
     - fornitori Italia: 2.03.08.xxxx
     - fornitori estero: 2.03.09.xxxx
     - professionisti: 2.03.10.xxxx
     - clienti Italia: 1.02.20.xxxx
     - clienti estero: 1.02.21.xxxx
   - Serve per partitario, partite, scadenze, pagamento/incasso, scrittura finale.
   - Deve essere mostrata nella prima colonna della working table sotto il nome estratto XML.
   - Esempio:
     DAC Spa
     2 03 08 0306 - DAC Spa
   - Se non collegata, deve comparire “Non collegato” o “-”.
   - Se manca, la fattura non è pronta/registrabile.

2. Conto costo/ricavo
   - È la colonna “Conto” / “Conto proposto” della working table.
   - È separato dalla controparte patrimoniale.
   - È gestito da manualAccountByRowId.
   - NON deve mai ricevere il conto patrimoniale fornitore/cliente.
   - Priorità futura proposta conto costo/ricavo:
     1. preimpostazione sull’anagrafica piano conti della controparte;
     2. storico contabilizzazioni;
     3. impostazioni generali procedure/studio, futura tabella.

3. Causale contabile
   - Separata dal conto.
   - Gestita da manualCausaleByRowId.
   - In futuro deve derivare da tabella “Studio / Impostazioni procedure”, non da storico:
     - fattura fornitore ordinaria: FF
     - fattura cliente ordinaria: FC
     - IVA per cassa: FFPC / FCPC
     - fattura/parcella con ritenuta: RP / RPPC
     - estero/reverse: A17X / FARC, fase successiva
   - Operatore può sempre variare.

4. Percipienti
   - Gestione integrata dentro “Anagrafiche da verificare”, non tabella separata.
   - Filtro Tipo include: Fornitore, Cliente, Percipiente.
   - Le righe percipiente devono stare in alto.
   - Match percipiente SOLO su codice fiscale.
   - CF obbligatorio.
   - Nessun match su P.IVA.
   - Nessun match su denominazione.
   - Se CF esiste già in anagrafica percipienti, NON creare nuovo percipiente.
   - P5 non collega CU/770/scadenzario ritenute.
   - Cassa previdenziale/ritenute dettagliate ancora non implementate nel parser/anagrafica percipiente.

5. Working table
   - Prima colonna: fornitore/cliente XML + conto patrimoniale collegato sotto.
   - Colonna Conto: conto costo/ricavo.
   - Colonna Causale: causale contabile.
   - Readiness riga richiede:
     - numero documento
     - data documento
     - imponibile
     - IVA presente/parsata, ma senza detrazione IVA
     - totale
     - controparte patrimoniale collegata
     - conto costo/ricavo
     - causale contabile
   - Detrazione IVA, indetraibilità, pro-rata, split payment, reverse charge, registri IVA vanno nella working view avanzata, non nella readiness P5.
   - Complete/Incomplete usano readiness finale.
   - “Pronta” deve poi essere resa visivamente verde tipo Imported; “Incompleta” gialla/rossa in P6 UX.
   - La colonna Stato attuale è probabilmente poco utile; in P6 valutare sostituzione/spostamento e inserimento “data registrazione” più a sinistra.

6. Working view
   - È separata dalla working table.
   - Click “Avvia contabilizzazione” apre schermata dedicata, non pannello sotto la tabella.
   - Layout attuale/futuro:
     - sinistra: anteprima fattura
     - destra: working view contabile
   - Pulsanti:
     - Torna all’elenco
     - Riga precedente
     - Riga successiva
     - indicatore 1 / N
   - Navigazione:
     - se righe selezionate: naviga solo tra selezionate pronte;
     - se nessuna selezione: naviga tutte le righe pronte;
     - incomplete escluse.
   - Working view P5 è locale/read-only:
     - nessun DB write
     - nessun commit reale
     - nessuna prima nota reale
     - nessun documenti_contabilita
     - nessun documenti_import
     - nessun partitario
     - nessuna IVA/ritenute/CU/770
   - Controlli strutturali P5J2:
     - controparte patrimoniale presente
     - conto costo/ricavo presente
     - causale presente
     - dati documento
     - quadratura bozza PN
     - partitario coerente
     - IVA base presente
   - Status: ok / warning / blocked.

7. Snapshot / local state
   - manualAccountByRowId = conto costo/ricavo.
   - manualCausaleByRowId = causale.
   - anagraficheDecisioniByKey = decisioni anagrafiche.
   - percipientiDecisioniByKey = decisioni percipienti.
   - counterpartyAccountByRowId = derivato per conto patrimoniale controparte.
   - Snapshot deve restare compatto, niente payload pesanti.
